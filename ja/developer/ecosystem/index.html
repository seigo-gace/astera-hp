独自開発・エコシステム

Astera本体と役割を分けて連携するTGserver、Webhook Gateway、Libral-Vaultを紹介します。

Asteraと周辺Systemを分ける理由

Asteraは判断材料を作るCoreだけですべての責務を抱え込まず、外部Event、運用記録、保護情報を専門Systemへ分けて連携できる構造を取っています。

外部Service→Webhook Gateway→Astera / Application→TGserver / Libral-Vault

3つの独自System

TGserver

Systemで何が起きたかを後から確認できるよう、運用記録・Audit・障害情報を実行本体と分けて扱います。

TGserverを詳しく見る →
Webhook Gateway

決済や外部Serviceから届くEventを受け取り、必要なSystemへ安全に渡す外部Event連携基盤です。

Webhook Gatewayを詳しく見る →
Libral-Vault

認証情報など保護が必要な情報を、通常のApplication処理や利用者Dataと分けて扱う保護基盤です。

Libral-Vaultを詳しく見る →

公開する範囲

各Systemが何のために存在し、Asteraとどう責務を分けるかまでは公開します。内部Network、Secret、監視値、復旧手順、攻撃や再現に利用され得る核心実装は公開しません。
