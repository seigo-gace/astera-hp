# 法人・協業相談
Asteraは、主役AIを置き換えるのではなく、AIへ渡す問いと、AI回答を採用する前の確認・比較工程を外側から強化します。法人利用では、個人の経験だけに依存している判断工程を共通化し、重要な前提、未確認情報、Risk、反対意見、比較条件、判断理由を引き継ぎやすくします。

## 法人で起きやすい課題
- 部署や担当者ごとに確認方法が異なる
- AI回答の根拠と前提を再調査している
- 会議や稟議の前に論点が揃っていない
- 反対意見や撤退条件が残らない
- 導入したAI・Toolごとに判断工程が分断される
- Security、Privacy、法務、運用確認が後付けになる

## Asteraが提供する判断材料
1. 本当の目的
2. 前提不足
3. 事実確認
4. 危機察知
5. 反対視点
6. 比較案
7. 推奨判断
8. 主役AIへの再指示

最終決裁、承認、契約、専門判断は、権限を持つ人または組織へ残します。

## 利用例
### AI回答・資料の事前確認
公開前の資料、企画、AI回答、設計を、前提、Evidence、Risk、反対、比較の観点から確認します。

### 会議・稟議
論点、追加Evidence、決定条件、保留条件を会議前に整理します。

### Tool・Vendor導入
費用、移行、解約、Data、Security、障害、Vendor依存を同じ基準で比較します。

### 開発・Architecture
要件、責務、依存、異常系、Security、運用、復旧、Test条件を整理します。

### 法人Knowledge
権限範囲内の規定、手順、製品情報、専門Knowledgeを接続し、公開Knowledgeと混同しない形で利用します。

## 導入形態
- Astera Web App
- Team利用
- API接続
- Webhook・業務Flow
- Private Knowledge
- 外部Storage
- 専有・個別構成

提供中、Beta、公開準備中の機能は区別して案内します。

## Data・Privacy
- 入力Dataの権利は利用者または正当な権利者へ残す
- 最小限のDataだけを処理する
- 保存、削除、Export、国外処理を明示する
- 外部AIを使う場合はProviderと送信範囲を表示する
- Secretや認証情報を通常処理から分離する

詳細は[プライバシーポリシー](/legal/privacy/)で確認できます。

## Security
Access制御、最小権限、通信保護、入力検証、Rate Limit、Audit、Secret分離、障害対応を組み合わせます。内部Network、鍵、監視値、復旧手順等は公開しません。

## PoCの流れ
1. 解決したい課題を確認
2. 対象Dataと権限を確認
3. 成功条件と測定方法を定義
4. Security・Privacy・法務を確認
5. Scope、期間、責任分界を合意
6. 実施
7. 導入前後を評価

## 協業
API連携、AI製品への組込み、専門Knowledge、Security、Accessibility、検証、販売・導入協力等の協業を受け付けます。必要に応じてNDAと個別契約を締結します。
